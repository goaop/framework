Upgrading from 3.x to 4.0
=========================

Go! AOP 4.0 replaces the inheritance-based weaving engine with a trait-based one, generates advices
as first-class callables, and rebuilds the caches for PHP 8.4. Most applications only need the
steps in "Quick checklist". The sections after it describe every breaking change. The full list
of changes is in the [CHANGELOG](CHANGELOG.md).

Quick checklist
---------------

1. Run on PHP 8.4 or newer and update the dependencies (see [Requirements](#requirements)).
2. Make every advice method of your aspects `public` (see [Aspects](#aspects)).
3. Register aspects with `add()`/`addLazyService()` instead of `registerAspect()`.
4. Replace `?` wildcards in pointcut expressions with `*` and rewrite `dynamic(...)` pointcuts.
5. Delete the AOP cache directory, then warm it up again (`bin/aspect cache:warmup:aop`).
6. If you use the Doctrine bridge, switch entity discovery to `WovenEntityClassLocator`.

Requirements
------------

- PHP 8.4+ with `ext-tokenizer`.
- `goaop/parser-reflection` ^4.0, `goaop/dissect` ^4.0, `symfony/finder` ^7.4 || ^8.0.
  `nikic/php-parser` 5 is installed through parser-reflection.
- `laminas/laminas-code` is no longer used: proxies are generated by the internal
  `Go\Proxy\Generator` package. Code that extended the framework generators or relied on laminas
  generator classes coming with the framework has to be updated.
- `bin/aspect` needs `symfony/console` ^7.4 || ^8.0.

Caches
------

Every cache format changed, and no 3.x cache file is reused:

- **Proxy layout.** The `_proxies` subdirectory is gone. A proxy is stored at the relative path of its
  source file below the cache directory, and the woven source (the original class body as a
  `<Class>OriginalTrait` trait) next to it.
- **Class map.** `_include.cache` maps every woven class to its cached file and is handed to Composer
  at boot. A cache directory without it is treated as stale.
- **Advisor cache.** The serialized `{cacheDir}/_aspect/sha1(FQCN)` blobs are replaced by plain PHP
  files next to the woven sources: `{appDir}/src/Aspect/LoggingAspect.php` is cached as
  `{cacheDir}/src/Aspect/LoggingAspect.cache.php`. Interceptors are no longer serializable
  (`AbstractInterceptor::__serialize()`/`__unserialize()`, `serializeAdvice()` and
  `unserializeAdvice()` are removed).

**Action:** delete the cache directory when upgrading. On a read-only production file system, build
the cache at deploy time with `bin/aspect cache:warmup:aop` before switching traffic.

`Features::PREBUILT_CACHE` now trusts the cache completely. Directory and writability probes,
`filemtime` comparisons, tracked-resource checks and advisor cache freshness checks are all
skipped. Rebuilding the cache on deploy is the deployer's responsibility.

The `cacheFileMode` option is validated. It must be an integer between `0600` and `0777` that grants
the owner read and write access. Directories get search permissions matching the read bits of the
mode.

Aspects
-------

### Advice methods must be public

Generated proxies call advices as first-class callables on the aspect instance, so a method with
`#[Before]`, `#[After]`, `#[Around]` or `#[AfterThrowing]` must be `public`. The aspect loader throws
an `AspectException` for protected or private advice methods. Methods that only carry
`#[Pointcut]` may keep any visibility.

```php
// 3.x
#[Before('execution(public Example->*(*))')]
protected function beforeMethod(MethodInvocation $invocation): void {}

// 4.0
#[Before('execution(public Example->*(*))')]
public function beforeMethod(MethodInvocation $invocation): void {}
```

### One advice attribute per method

An aspect method carries at most one of `#[Before]`, `#[After]`, `#[Around]` and `#[AfterThrowing]`; a second one
throws an `AspectException`. Split such a method into one method per advice. `#[Pointcut]` may still be combined with
an advice on the same method, and attributes that do not belong to the framework are ignored.

### Registering aspects

`AspectContainer::registerAspect()` is removed. Aspects are ordinary container services:

```php
// 3.x
protected function configureAop(AspectContainer $container)
{
    $container->registerAspect(new MonitorAspect());
}

// 4.0
protected function configureAop(AspectContainer $container): void
{
    // Deferred (recommended): constructed when one of its advices runs for the first time
    $container->addLazyService(MonitorAspect::class, static fn() => new MonitorAspect());

    // Eager alternative
    // $container->add(MonitorAspect::class, new MonitorAspect());
}
```

`addLazyService()` stores a factory and builds the service on its first retrieval. Code that
expected a lazy-proxy instance to exist at boot must call `getService()`. A factory returning an
object of the wrong type now fails on first use, not at registration.

`AspectContainer::addResource()` is part of the interface. `onRegistration()` lets you react to
deferred registrations of services implementing an interface.

### Advice and interceptor API

- The `AdviceBefore`, `AdviceAfter` and `AdviceAround` marker interfaces are removed. `Advice`
  requires `getType(): AdviceTypeEnum` (`Before`, `After`, `AfterThrowing`, `Around`,
  `Introduction`).
- The invocation constructors (`DynamicTraitAliasMethodInvocation`,
  `StaticTraitAliasMethodInvocation`, `ReflectionFunctionInvocation`) require a non-nullable
  `Closure $closureToCall`.
- `DeclareError` (the attribute, `DeclareErrorInterceptor` and `PointcutBuilder::declareError()`) is
  removed. Emit warnings or throw exceptions from a `#[Before]` or `#[Around]` advice instead.

Pointcuts
---------

- **`?` wildcard removed.** `?` in name and type patterns is no longer a single-character wildcard,
  because it collided with nullable types. In return-type patterns a leading `?` is a nullable
  marker (`?Foo` equals `Foo|null`). Replace `?` wildcards with `*`.
- **`dynamic(...)` pointcut removed**, together with `MagicMethodDynamicPointcut`,
  `DynamicInvocationMatcherInterceptor`, `Pointcut::KIND_DYNAMIC` and the
  `$instanceOrScope`/`$arguments` parameters of `Pointcut::matches()`. Intercept the magic method
  itself and read the invoked name from the arguments:

  ```php
  // 3.x
  #[Around('dynamic(public Foo->save*(*))')]

  // 4.0
  #[Around('execution(public Foo->__call(*))')]
  public function aroundMagicCall(MethodInvocation $invocation): mixed
  {
      [$methodName, $arguments] = $invocation->getArguments();
      // ...
      return $invocation->proceed();
  }
  ```
- **Modifier precedence.** Space-separated modifiers must all be present and `|` binds tighter:
  `final public|protected` means final AND (public OR protected). In 3.x it also matched every non-final public
  method.
- **`Foo+` includes `Foo`.** It now also matches the class or interface `Foo` itself and classes that use the trait
  `Foo`. Add `&& !within(Foo)` to exclude the type itself.
- **Attribute pointcuts match subclasses.** `@execution(Attr)` and friends also match attributes extending `Attr`.
- **`ModifierPointcut` is final and immutable.** The masks are constructor arguments, and
  `andMatch()`, `orMatch()` and `notMatch()` return a new instance.

Weaving engine and generated code
---------------------------------

The original class body is converted into a trait, `<Class>OriginalTrait`. The proxy class keeps the
original name, parent and interfaces, and uses that trait with private `<method>OriginalAlias`
aliases. In 3.x the proxy extended a renamed `<Class>__AopProxied` parent class. This affects code
that relied on that inheritance layer:

- The proxy has no renamed parent class any more. `get_parent_class()`, `parent::` inside the
  class and `instanceof` checks see the original parent.
- `AspectContainer::AOP_PROXIED_SUFFIX` is `'OriginalTrait'`.
- `AbstractMethodInvocation::TRAIT_ALIAS_PREFIX` is replaced by `TRAIT_ALIAS_SUFFIX`
  (`'OriginalAlias'`).
- The hooks of `InitializationAware` and `StaticInitializationAware` are named
  `__initialization()` and `__staticInitialization()`.
- `self::` in woven code resolves to the proxy class, so `SelfValueTransformer` and
  `SelfValueVisitor` are removed.
- `Features::PARAMETER_WIDENING` is removed. Delete the flag from your kernel options if you
  passed it.

Kernel and transformers
-----------------------

- `AspectKernel::registerTransformers()`, which returned transformer instances, is replaced by
  `registerTransformerServices(AspectContainer $container)`, which registers deferred container
  services. Override it to replace, omit, reorder or extend the built-in transformers, or append
  one with `$container->addLazyService(MyTransformer::class, ...)` from `configureAop()`.
- `CachingTransformer` is removed: the cache decision lives in `SourceTransformingLoader`.
  `SourceTransformingLoader::addTransformer()` is removed, and `transformCode()` returns the overall
  `TransformerResultEnum`.

Exceptions
----------

Every exception thrown by the framework implements `Go\Aop\Exception\ExceptionInterface`, so one `catch` handles
any Go! AOP failure. Several throw sites changed their type:

| Situation                                                        | 3.x                                                    | 4.0 |
|------------------------------------------------------------------|--------------------------------------------------------|-----|
| Invalid kernel options, container registrations, console input  | `RuntimeException`, `InvalidArgumentException`, `UnexpectedValueException` | `InvalidConfigurationException` (an `InvalidArgumentException`) |
| Invalid pointcut expression                                      | `UnexpectedValueException`, `InvalidArgumentException` | `PointcutSyntaxException` (an `AspectException`) |
| Unknown container id                                             | `OutOfBoundsException`                                 | `ServiceNotFoundException` (an `OutOfBoundsException`) |
| Weaving, proxy generation, cache writes                          | `RuntimeException`, `LogicException`, `InvalidArgumentException` | `WeavingException` (a `RuntimeException`) |
| Advisor that can not be cached                                   | `Go\Core\Cache\NotCompilableException`               | `Go\Aop\Exception\NotCompilableException` |

**Action:** catch `ExceptionInterface` or the new types where you caught the SPL types listed above.

Doctrine bridge
---------------

The bridge no longer rewrites entity metadata. The 3.x mapped-superclass workaround only applied to
the extend-based engine, and Doctrine maps a woven entity correctly as it is. Two things need to be
configured instead (Doctrine ORM 3.6+):

```php
use Doctrine\ORM\Events;
use Doctrine\ORM\Mapping\Driver\AttributeDriver;
use Go\Bridge\Doctrine\MetadataLoadInterceptor;
use Go\Bridge\Doctrine\WovenEntityClassLocator;

// Discover entities through the autoloader, which serves the woven classes
$configuration->setMetadataDriverImpl(
    new AttributeDriver(WovenEntityClassLocator::createFromDirectories([__DIR__ . '/src/Entity'])),
);
// Intercepted properties become hooked properties, which Doctrine supports with native lazy objects
$configuration->enableNativeLazyObjects(true);

// Optional: reports misconfiguration early; a plain listener, no longer an EventSubscriber
$eventManager->addEventListener(Events::loadClassMetadata, new MetadataLoadInterceptor());
```

Console
-------

The commands declare their names with `#[AsCommand]` and are loaded lazily by `bin/aspect`. Every
command returns `Command::SUCCESS` or `Command::FAILURE`. In 3.x `debug:weaving` returned the raw
error count, so check the exit code instead if a script relied on that number. `cache:warmup:aop`
fails when a file cannot be woven (add `--fail-fast` to stop at the first error), so a deploy script
that ignored warmup errors now stops there.
