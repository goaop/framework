# src/Instrument/Transformer/Weaving — weaving internals

Three `@internal` classes behind WeavingTransformer (src/Instrument/Transformer/WeavingTransformer.php):

| Class             | Role                                                                                |
|-------------------|-------------------------------------------------------------------------------------|
| TokenStreamEditor | Line-preserving token edits of one StreamMetaData, addressed by AST token positions |
| TraitConverter    | Source of an advised class/enum/trait → the woven trait (`<Name>OriginalTrait`)     |
| ProxyCache        | Writes class/function proxies into the cache dir, returns their include statements  |

Proxy code itself is generated by src/Proxy (ClassProxyGenerator, EnumProxyGenerator, TraitProxyGenerator,
FunctionProxyGenerator), see src/Proxy/AGENTS.md. The woven/proxy file shapes are in src/Instrument/AGENTS.md.

## WeavingTransformer::transform() — orchestration only
1. `new ReflectionFile($uri, $syntaxTree)` + one `TokenStreamEditor` for the file.
2. Load unloaded aspects (`AspectLoaderInterface::getUnloadedAspects()` → `loadAndRegister()`), read all Advisors.
3. Per namespace block, per class-like:
   - `CachePathManager::registerClassForResource()` for every class (woven or not: runtime class map / skip set).
   - Interfaces are skipped. weaveClass():
     - `getAdvicesForClass()`; a matching failure is swallowed only for an aspect (`isAspectSafe()`), else rethrown.
     - No advices → skip. Only then `implementsInterface(Aspect::class)` → skip (it reflects every ancestor, #748).
     - `flatAndSortAdvices()`, trait name `<Short>OriginalTrait`, original imports of THIS namespace block,
       `ClassProxyGenerator::indexMethods()` (method index shared with the generators).
     - `TraitConverter::convert()`, then the generator by kind (trait / enum / class), `declare(strict_types=1);`
       prepended when the source file uses strict mode.
     - Returns `[class, proxyCode, lastTokenPosition]` (`range(classNode)[1]`, the closing brace).
   - Functions of the namespace: skipped in the global namespace (would redeclare internal functions);
     `getAdvicesForFunctions()` → `ProxyCache::saveFunctionProxy()` → include appended to the last namespace token.
4. After the whole file: `ProxyCache::saveClassProxy()` per woven class (layout depends on the woven class COUNT,
   hence the buffering), include appended after the class' last token (`PHP_EOL . include`).
5. Transformed if any class or namespace was woven, else Abstain.

WeavingTransformer runs after SyntaxTreeRewriter and sees its token edits: the rules change token text and unset
single whitespace tokens (ConstructorExecutionTransformer, FilterInjectorTransformer). Positions are never renumbered,
so node positions stay valid and the editor skips the removed ones.

## TokenStreamEditor
Bound to one StreamMetaData (`final readonly`, holds the object; edits `$metadata->tokenStream` in place).
- Positions are the keys of `StreamMetaData::$tokenStream` = the parser's `startTokenPos`/`endTokenPos` attributes.
  Removed (`unset`) positions are skipped by every method; nothing is ever renumbered or inserted.
- `static range(Node): array{int,int}` — throws `WeavingException::declarationWithoutTokenPositions()` (class name
  for a ClassLike, `$node->getType()` otherwise) instead of every caller silently skipping such nodes.
- `static rangeAfterAttributes(ClassLike|Param)` — start moved right after the last attribute group: the node start
  includes `#[...]`, scanning from there renamed a T_STRING inside the attribute (#598).
- `token(pos): ?PhpToken`, `find(text, start, end): ?int` (first token with that exact text in the range).
- `replace(pos, text)`, `prepend(pos, text)`, `append(pos, text)` — no-ops on removed positions.
- `blank(start, end, replacement = '', keepWhitespace = false)` — every token keeps only its newlines;
  `$replacement` goes in front of the first non-removed token (markers, must be newline-free); `keepWhitespace`
  leaves T_WHITESPACE tokens as they are (brace placement in headers).
- `remove(start, end)` — unsets tokens (enum cases: the whitespace after the case stays, so lines stay).
- `removeWithInlineWhitespace(pos)` — unsets the token and the next token if it is T_WHITESPACE WITHOUT a newline
  (`final class` → `class`, `final\nclass` keeps its line). Used for modifiers and trailing commas.

Line budget rule: never delete a newline, never put a newline into a replacement.

## TraitConverter::convert(class, advices, methods, editor, traitName)
Reads from `$advices`: intercepted methods = keys of METHOD_PREFIX + STATIC_METHOD_PREFIX (they get a trait alias in
the proxy), intercepted properties = keys of PROPERTY_PREFIX (re-declared by the proxy with native hooks).
First step for every kind: `assertNoTraitImportedOverride()` (throws before any token is edited).

Steps per kind (order kept from the former implementation, edits touch disjoint token ranges):

| Kind  | Steps                                                                                                  |
|-------|--------------------------------------------------------------------------------------------------------|
| trait | intercepted property items → rename → strip #[\Override]                                               |
| enum  | header → blank EnumCase statements + their doc comments → strip #[\Override]                           |
| class | header → readonly class: `readonly` on every property (makePropertiesReadonly) → intercepted property items + promoted properties → strip #[\Override] → trait-incompatible class attributes |

### Header (rewriteHeader)
- Name: `range($node->name)[0]` → replaced by the trait name (anonymous classes never get here).
- `[rangeAfterAttributes(node)[0], namePos)`: T_FINAL/T_ABSTRACT/T_READONLY → `removeWithInlineWhitespace`,
  T_CLASS/T_ENUM → `trait`. Comments/whitespace there are untouched. Traits have none of these tokens.
- Clauses: last node of `[extends, ...implements]` (Class_) or `[scalarType, ...implements]` (Enum_);
  `blank(namePos + 1, range(lastClause)[1], keepWhitespace: true)` — keywords, names, commas and the backed type
  `:` become empty, whitespace (and with it the brace placement and multi-line `implements` lists) stays.

### Readonly class (makePropertiesReadonly, #792)
The header loses T_READONLY (traits can not be readonly) while the proxy class stays readonly, and PHP rejects a
readonly class using a trait with a non-readonly property. So for a `readonly class`, `prepend(range(type)[0],
'readonly ')` on every Property statement and promoted constructor Param without the flag (fallback: first item /
the variable when untyped): `public int $x` → `public readonly int $x`, same line. Properties of a readonly class are
readonly for parser-reflection, so AdviceMatcher never intercepts them: no overlap with the property removal step.

### Enum cases
Every EnumCase statement: `blank(range(case))` (attributes included, newlines kept: an attribute on its own line keeps
its line) and `blank()` of its doc comment, which PHP would otherwise give to the next trait method (#794).
EnumProxyGenerator re-declares the cases in the proxy enum with their attributes and doc comment.

### Attributes (removeAttributes, shared by #[\Override] and the class attributes)
Per AttributeGroup, `$shouldRemove` picks attributes:
- all of the group's attributes picked → `blank(range(group))`;
- else each picked attribute: `blank(range(attr))`, then ONE comma: the trailing one, found with `find(',')` between
  the attribute end and the next attribute start (or the group's `]`), removed with `removeWithInlineWhitespace`;
  none → the leading one between the previous attribute (or `#[`) and the attribute, plain `remove`.
  Result examples: `#[A, B]` minus A → `#[B]`; minus B → `#[A ]` (whitespace before the removed entry stays).
- Attribute names: `resolvedName` attribute of the name node (parser-reflection runs the NameResolver without
  replacing nodes), fallback to the name as written, leading `\` trimmed. So `use Override as O; #[O]` is Override,
  `#[Foo\Override]` is not.

### Trait-incompatible class attributes (#615)
`#[\Attribute]`, `#[\AllowDynamicProperties]` are compile-time errors on traits ("Cannot apply #[\Attribute] to
trait"): removed from classes only. The proxy class copies the original attribute groups from the AST
(AttributeGroupsGenerator), so the proxied class still reports them.

### #[\Override] on intercepted methods (PHP 8.3+)
PHP copies the attributes of a method to its trait alias (`m as private mOriginalAlias`); the alias overrides nothing,
so #[\Override] there is a fatal error at load time.
- stripOverrideAttributes(): for every intercepted method whose DECLARING class is the woven class (methods imported
  from a trait report the using class in `class` but their attributes live in the trait file), remove #[\Override]
  via removeAttributes(). Applies to classes, enums and woven traits (TraitProxyGenerator aliases them the same way).
  The proxy method keeps the attribute (MethodGenerator copies it from the AST), so PHP still checks the override.
- assertNoTraitImportedOverride() (#761): a method whose `class` is the woven class but whose declaring class is
  ANOTHER trait, carrying #[\Override], can not be stripped per class (shared trait file) → throws
  `WeavingException::traitImportedOverrideNotInterceptable(class, method, trait)`. Native reflection hides this case
  (it reports the using class as declaring class), so the proxy generators can not detect it. Covers trait aliases,
  static methods, enums, woven traits using a trait. Methods inherited via a parent class keep the parent in `class`
  and are called through `parent::m(...)` without alias → fine. Nested traits are not collected by parser-reflection.
- User workarounds: `&& !matchInherited()` (excludes trait-imported methods too), a narrower
  `&& !execution(public Foo->hello(*))`, drop #[\Override] from the trait method, or advise the trait itself
  (`execution(public HelloTrait->hello(*))`, intercepts it in every class using the trait).

### Intercepted properties (removePropertyItems, #669)
Per `Property` statement of the class/trait body (own declarations only, grouped declarations handled per item):
- all items intercepted → `blank(range(statement), markers)`: attributes, modifiers, type, items and `;` go, newlines stay;
- else each intercepted PropertyItem → `blank(range(item), marker)`; the separating comma between items k and k+1
  (`find(',')` between their ranges) is emptied unless item k is kept AND a later item is kept:
  `public int $a = 1, $b;` minus `$a` → `public int /* Moved… */ $b;`.
- Marker: `/* Moved by weaving interceptor to the {@see Class->prop} */`, newline-free. NEVER a `//` prefix: a
  multi-line declaration would stay live after the first line.

### Promoted constructor properties (#599)
Classes only (not traits). The declaration doubles as the constructor parameter, so it can not be removed:
- Parameters come from `$classNode->getMethod('__construct')->params` (own constructor node → only tokens of this
  file are edited): `isPromoted()` and the variable name intercepted.
- removePromotionModifiers(): in `[rangeAfterAttributes(param)[0], range(param->type ?? param->var)[0])` every
  T_PUBLIC/T_PROTECTED/T_PRIVATE/T_*_SET/T_READONLY/T_FINAL → `removeWithInlineWhitespace`. Attributes, type, `&`,
  name and default stay.
- Assignments `$this->x = $x;` (parameter order) appended to the body `{`: the first `{` after the end of the LAST
  parameter (hook bodies and PHP 8.5 closures in defaults lie inside the parameter ranges), on the same line, so the
  write goes through the proxy's set hook and the constructor statements keep their lines. An abstract constructor has
  no `{` → nothing appended.

## ProxyCache
Constructed by WeavingTransformer with the CachePathManager, the container and the `appDir` option.
- `saveClassProxy(class, code, isOnlyClass): string`
  - no cache dir or `getFileName() === false` → `''` (the woven file still gets an empty include line appended).
  - relative path = `PathResolver::rebase(file, appDir, '')`, or the absolute path when outside appDir, `\` → `/`.
  - only woven class of its file → `<cache>/<relative path>`; several → `<cache>/<relative path>/<Ns>/<Class>.php`,
    the source path used as a directory like a file inside a phar (#760).
  - layout switch (file ↔ directory at `<cache>/<relative path>`) → the other layout is removed first.
  - content `'<?php' . PHP_EOL . code` through `CachePathManager::getCacheFileWriter()` (atomic tmp + rename).
  - returns `include_once AOP_CACHE_DIR . '/<path>';`
- `saveFunctionProxy(namespace, Closure(): string $generate): ?string`
  - no cache dir → null (namespace counts as not woven).
  - one file per namespace `<cache>/_functions/<Ns>.php`, shared by every file declaring functions in it; regenerated
    only when missing or `!$container->isFreshSince(filemtime)`; the closure runs only then.

## Why not format-preserving printing
php-parser's `printFormatPreserving()` (parser-reflection keeps the tokens) was measured against these edits:
lossless for flags, renames and param flags, but removing a multi-line `extends … implements`, a property statement or
an enum case drops lines (XDebug mapping breaks), `class` → `trait` forces a reprint of the whole class (node type
change), and the bytes differ from the token edits (`#[First]` vs `#[First ]`, no Moved marker). It would also cost a
clone + print + re-tokenize per woven file. Token edits addressed by node positions are kept instead.
